# Portable 全面架构审计与整改清单 · 2026-09-22

## 结论与证据边界

核心交付能力值得保留：隔离数据路径、便携运行环境、双通道更新、事务恢复、独立诊断和离线准备。当前更需要收敛所有权、补丁和交付证据，而不是再叠一层管理界面，也不是无证据地全部重写。

本轮是跨模块源码审查、官方能力比对、线上流程回读和定向边界测试。**不是每行代码的完整安全审计，也不是各平台成品重新验收。** 下表把确定缺口、待复现风险和验收空白分开；未完成项不隐去，不用测试总数代表覆盖完整。

基线：Portable main `978a9217c323843e488a35b6a4430300fc13ba83`，另含本地未提交的行内插件更新改动；当前产品版本字段 `0.7.0-beta.3`。这些 UI 改动是本地预览，不能称为公开交付。

现场原始证据在 `build/architecture-audit-20260922/`：inventory.json、官方源文件快照、market-delta.json、core-sync-failed.log、boundary-tests.log。没有扫描用户会话正文、修改插件启用状态或清理用户数据。

## 推进顺序与验收规则

1. A01–A06：先让运行身份、插件实际交付、并发所有权、同步失败和安全告警可解释，避免扩大本地预览范围。
2. A07–A13：官方Plugin Manager成为现代宿主的操作中心；市场侧收缩为发现和必要版本信息，默认插件保留可证明的差异能力。
3. A14–A23：延续U01–U04、T01–T04、S01和Q01，收敛更新、恢复、长期清理与壳职责。
4. A24–A34：有测量依据的瘦身/性能与官方桌面原型，改进CI和文档。不能用“将来换Electron”拖延当前确定bug。

每项关闭记录：复现/现状 → 所有权决定 → 最小实现/删除范围 → 定向测试 → 真实候选验收 → 发布/安装身份。对只完成调查的项目，明确写“源码审查”或“待实机”，不能勾成产品完成。

本轮边界测试：119项，113通过，6跳过，0失败。四项为当前Windows账户无法创建文件symlink；两项仅适用POSIX。范围：update-core、runtime-capsule、repair-core、storage-report、data-transfer-security、plugin-command-lock、plugin-market-update-recovery。没有运行全量平台CI，也没有做断电、macOS/Linux原生、长稳或全数据恢复验收。

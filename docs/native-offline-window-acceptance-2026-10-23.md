## 实现与安全边界

- Windows Native 提供六项可选窗口能力；默认原生栏，页面导航/错误复位，托盘可强制恢复。没有内置视觉插件、皮肤选择或新旧 UI 切换。没有声明能力的宿主不显示或调用相应入口。
- 离线输入始终验证原始清单和 detached signature，再核实际 ZIP 长度与 SHA-256。组件沿用现有预检、事务、健康检查和回滚；完整 Windows 包委托现有 FullUpdater，并由它再次验签、复制与核摘要。
- Node CLI 没有签名密钥覆盖选项，未知签名与 `--allow-http` 组合也不能绕过。缺附件、摘要错误、错误平台或组件不兼容均不联网补取。内核契约 2 不接受契约 1；旧版宿主不能识别离线请求时不展示按钮。
- 整包离线操作启动的预检、健康验证及恢复进程会继承本次专用的跳过自动检查/内核恢复标记，避免新进程借启动流程联网；不修改保存的偏好，下次普通启动仍按原设置执行。新增组合场景显式让父进程标记为 0，两个真实子进程必须观察到 1 才能报告 ready，实际通过。
- 实际切换至 rc.1 时，其已签名胶囊带有旧版 Portable 页面模块，没有新设置按钮。Native 帮助菜单因此固定提供两个离线入口，同用既有处理与任务禁用规则；不为补 UI 重打包或重新发布旧内核，不增加另一套更新逻辑。
- 独立静态审查未发现新增的实质缺陷；这不是全面安全审计或无漏洞保证。1.x 官方 Electron ASAR 的 MCP 重定向风险仍按[安全跟进记录](one-x-mcp-followup-2026-10-23.md)阻断，不修改官方包或豁免检查。

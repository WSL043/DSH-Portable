# Native 维护交付：固定验收标准

范围冻结日期：2026-09-27。本文定义下一次 Native 维护交付的完成条件，替代“把 A01–A34 全部长期方向做完才算完成”的无限范围。长期请求仍保留在维护总表，不因本次划分被删除或标为完成。

## 唯一完成定义

下列 G1–G8 按本文件记录验收，且证据对应最终候选代码、随包内核和默认插件组合，才算本次交付完成。2026-09-28 用户要求重新审查关键发布标准后，G7 内存比例项适用下述仅限本次的明确例外；其原失败结果保持不变。研究记录、单元测试成功、工作流绿色、源码覆盖预览分别只能证明对应层次，不能互相替代。发布后还要回读发布文件、摘要及客户端索引；这些属于 G8，不另加一个隐含任务。

冻结后只接收这八项测试中发现的缺陷、安全/数据损坏问题及原功能回归。新功能、偏好调整、一般重构进入后续路线，不在验收期间临时加码。不能通过降低阈值、跳过失败、删除用户请求或把“阻断”改写为“通过”来收口。

## 不再拖动本批终点的长期方向

Electron 迁移（A25）、新的完整代码签名方案、Office 按需拆包、额外 Appshots 功能、市场视觉扩展、一般性模块重构及上游无关新能力不进入本批。它们继续保留编号与后续任务。发现其中存在影响当前产品的明确缺陷时，按受影响的 G 项处理，而不是整项研究都变成发布前置。

更正：#148 是全屏与保留任务栏最大化的入口需求，不等同于多屏/DPI专项。0.7.6已包含视图菜单的最大化/还原入口及明确的全屏文字；F11偏好设置未承诺实现，原生窗口边缘、任务栏行为的验收仍需单独闭环。真实多屏/100–200% DPI/输入法硬件矩阵另行跟踪。2026-09-28 用户明确确认本机不具备多屏验收环境，不将该专项作为本次发布前置；不启动模拟硬件验收，不关闭尚未验证的 issue，也不新增相应兼容承诺。跨机凭据若无法取得真实环境，不宣称可无损迁移，必须在产品说明中明确边界；普通数据迁移及中断恢复仍是 G4 的硬门槛。

## 执行和证据规则

1. 顺序固定为 G3 安全回收 → G4 中断恢复 → G2/G5 插件与内核链路 → G6/G7 操作和长稳 → G1/G8 冻结候选与发布。原有通过证据保留；只有影响其行为的改动才使对应证据失效。
2. 开发期间先跑受影响的测试和独立成品操作；收齐这一批改动后集中推送候选，再跑完整 CI。最终 CI 运行时不顺手新增不相关功能。
3. 失败记录实际操作、错误、产物身份及是否修改了数据。只有明确的外部/runner 短时故障允许一次不改输入的复验；再次失败必须调查。产品改动后生成新候选，不拿旧产物的成功作最终证据。
4. G7 在 G2/G3/G4 的分项检查通过后开始；可与独立平台构建并行。不得为等 CI 而重复执行已证明的相同故障实验。
5. 汇报固定为“本批 G1–G8 的状态、已通过的证据、唯一下一阻断项”。不再以 A01–A34 的全部长期方向作为每轮完成分母。所有 G 项完成后进入发布，不因为又想到一个普通优化而重开范围。

## 2026-09-28 执行审计后的纠正

- 门槛失败与产品缺陷分开记录。G7 超限已确认，但泄漏及 Portable 所有权尚未确认；先验证首末 UI 状态和预热可比性，不为未经归因的指标直接修改产品。
- 每项诊断开始前固定假设、唯一变量、时限和结果对应的决定。无收益的 MemoryUsageTargetLevel 与去模糊方向停止，不继续调参；已通过且未受改动影响的 G1–G6 不重跑。
- 唯一下一步为一次不超过10分钟的状态匹配预检：同一不可变隔离实例，首末均为相同页面与等价活动会话内容，记录 DOM、JS 堆及进程内存，禁止强制 GC。预检不是 G7，不变更其阈值。
- 若预检证明状态不匹配影响结论，修正验收方法并记录差异，再进行一次完整 G7；若仍超限或增长，不新增同类盲测，先定位具体原因与归属。两种结果都不得改写既有失败为通过。
- 子代理承担限时、窄范围的只读复核，主代理负责核验和决定。汇总采用现有记录，不为每次轮询另建文档；实验保留在独立 build 目录，退出核对所属进程，不触碰用户工作窗口。

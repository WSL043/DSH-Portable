# 导入中断恢复（G4）

2026-09-27 本地实现与定向证据。尚不代表最终不可变 Native 产物通过 G4，也不代表物理断电、跨机凭据或所有文件系统通过。

## 产品行为

导入开始时创建 `data/runtime/data-import.json`。每个文件写入前登记目标、备份身份和写入内容摘要；生成依赖目录在移动前登记恢复意图。原子写的临时文件也先登记，避免中断后猜测清理范围。普通数据仍通过原子替换写入，回滚使用已有备份的 rename，不依赖剩余空间重新复制数据。

重新导入、启动或修复会检测未完成事务。恢复先检查全部备份，再变更任何目标。已经被恢复操作消耗的备份，必须用目标的文件系统身份及普通文件内容摘要证明已经恢复；缺失或变化不算成功。导入后另行编辑的普通文件也不能被回滚静默覆盖。路径检查拒绝链接祖先与越界路径。生成目录只移动/移除其入口，不跟随链接。

提交记录只在写入和导入 profile 验证完成后写入。已提交事务重入只完成 journal 清理，保留原来的恢复快照；未提交事务恢复原状态。相对路径允许整个目录移动后恢复。同卷 rename 身份是这一机制的前提；不能将复制到另一卷后的身份变化当作已验证支持。

依赖命令由一个受记录的后台进程执行：先持久登记 PID 和随机进程身份标记，之后才允许启动官方 DSH 命令。恢复核对进程身份，避免 PID 复用被误判为原后台操作；正常结束后及时移除记录。Windows 不使用 detached 新建控制台，使用隐藏的继承进程作业。导入进程被强制结束时，Windows 可能同时结束所属进程树；若后台命令仍存活，恢复明确拒绝，等命令在既定超时内结束。超时结束命令进程树，输出有界，不因日志量大而提前释放写入保护。普通插件 CLI、备份导出、更新和插件隔离操作遇到未完成导入也拒绝执行，要求先修复。

受支持的操作要求该环境已停止，写操作共用 Portable 产品锁；涉及 profile 的官方 `package.json.lock` 若存在则拒绝，不删除未知锁。没有宣称能协调绕过 Portable 入口的 raw DSH CLI 或手工目录修改。

文件写入前先集中准备备份和完整清单，再执行替换，避免每写一个文件都重写不断增长的 JSON。每次只解码一个归档条目，不额外保留第二份完整归档；进度日志按首条及每千条记录。1000 个小文件的独立实测中，事务记录写入 426136 字节，导入约 1734ms；这是本机样本，不是所有设备的耗时保证。

Recovery 入口在加载运行时胶囊之前调用受产品锁保护的 `recover-data`；因此缺胶囊不会阻止已有数据事务回滚。完整运行文件仍缺失时，后续诊断继续报告需完整包，不把数据恢复成功当作整个产品修复成功。

## 可重跑证据

`tests/data-import-interrupt.test.mjs` 使用真实 fork 进程和 SIGKILL：

- 原子文件只写出部分内容、文件替换完成、依赖生成目录已移动、提交前、提交记录写完，五个边界分别强制结束。
- 整个目标目录移动后恢复，再次调用无副作用。
- 已恢复备份的身份识别、缺备份保留现场、导入后人工编辑不覆盖。
- 实际后台 Node 子进程仍活跃时拒绝恢复，退出后恢复。
- 真实 repair CLI 与 runtime-entry 入口；后者缺胶囊时仍先恢复数据。

`tests/data-import-worker.test.mjs` 验证登记失败不能执行、输出有界、错误转交、超时子进程树结束。现有 data-transfer、I/O 故障、安全路径、preflight、插件锁及 CLI 合同测试一同回归。Windows 无文件 symlink 权限的分支及 POSIX 专项保持条件跳过，不能算作本机证明。

Windows 隐藏进程修改经 subagent 只读复核后，以显式 Hidden 后台入口复验：108 项，102 通过、6 项平台条件跳过、0 失败，输出为 `build/data-import-20260927/hidden-tests.txt`。这确认了功能回归通过，不冒充前台焦点事件监测。`build/native-recovery-import-20260927-final/result.json` 的 Recovery.exe 源码覆盖验收通过 18 场景，包括缺胶囊指引、实际执行抛错插件、暂停后重新启动；不是最终不可变包。最终打包后的 Native 操作证据与跨平台 CI 仍按 G4/G8 收集，不拿这里的 Node 子进程测试冒充原生视觉验收。

# 完全离线部署：验收边界

状态：2026-09-10 本地修复验收中；以下新增修复尚未发布，不是企业隔离网认证。

## 预览底包纠正与解包优化

第一份 WebView2 预览沿用了旧验收底包，实际内核为 0.1.3-alpha.2，不能作为当前锁定内核的验收依据。现已以正式 RC2 资产重建，组件清单和实际启动日志均核对为 0.1.5-rc.1 / `183f08e9c6dde7e36cd2318eaee70b0da08fb35e`。完整离线构建增加产品版本、内核版本、提交和运行时支持入口检查，拒绝不匹配的底包。

同机同一 8,440 文件内核包，四次全新目标目录按旧实现、新实现、新实现、旧实现顺序测量：旧实现 3,675 / 3,381 ms，新实现 3,260 / 3,203 ms，平均改善约 8.4%。解压计算约 0.1 秒，主要耗时在文件写入。将每批 32 个文件的等待改为上限仍为 32 的连续工作队列；校验与原子提交保留，发生写入错误时等待所有在途写入结束后再清理。样本有限，属于本机调度收益，不代表所有磁盘或设备性能。

纠正后原生窗口验收使用空 DSH/WebView2 缓存：启动完成约 8.8 秒，缓存复用约 4.0 秒，均实际进入工作区。证据为 `build/corrected-native-evidence/` 与 `build/corrected-native-warm-evidence/`。新内核的独立离线后台测试也通过：两个默认插件成功安装、外网 TCP 尝试为零，证据为 `build/corrected-offline-backend-evidence/`。下面先前 1.3 内核的测量仅保留作历史记录，不能与另一台机器的耗时直接比较。

## 已复现并修复的首次启动缺陷

0.6.5-rc.2 的默认会话插件需要 `clsx`。包内只有插件压缩包，空缓存启动时仍会尝试从 npm 下载依赖。在拒绝 Node 外网 TCP 的测试中，启动约 73.6 秒后默认插件安装失败。

当前改动在构建阶段依据 `scripts/default-plugin-store/pnpm-lock.yaml` 的版本与完整性锁准备依赖存储及许可证，启动只使用本地存储，并限制默认安装等待时间。默认插件升级时需一并审查更新这份锁；构建拒绝锁与插件压缩包不一致的组合。内核更新继续只替换内核，默认插件存储随 Portable 完整包分发。

Windows 本地最终验收使用全新数据和运行时缓存：后台约 3.35 秒就绪，两个默认插件成功安装，外网连接尝试为零。证据在 `build/offline-fixed-acceptance-final/`；负向探测确实被拒绝。相关回归已接入 Windows CI，但该 CI 改动尚未远程运行。HTTP 根页要求认证，因此这项后台测试不等同于桌面 UI 或模型验收。

## 已确认的产品边界

- 已发布的 Windows 标准 ZIP 内含 Node、DSH 运行文件和默认插件，**不含模型权重、模型推理服务，也不含完整 WebView2 Runtime**。历史资产名中的 `offline` 保留下载兼容，展示文案不再称其为无前置条件的完整离线包。
- 本轮新增独立的 `DSH-Portable-windows-x64-complete-offline.zip` 构建规格，内含微软固定版 WebView2，不安装到系统。与标准包使用同一产品版本；尚未发布。两者均不携带模型权重。
- #128 的既有修复只证明浏览器离线信号不再阻断 localhost 连接，不代表已经通过完全断网的模型推理验收。
- 本机部署使用回环地址；内网部署仍需内网可达。在线模型、在线搜索、远程 MCP、下载新插件和在线更新不能在完全隔离环境中工作。
- 默认插件已预置不等于任意第三方插件及其依赖均能离线安装。企业镜像需要事先准备、验证所选插件和外部工具。

## 本轮验收方法

1. 使用独立 Portable 数据目录，不读取用户会话或凭据。
2. LM Studio 服务仅绑定 127.0.0.1；原 Qwen3-1.7B 未完成简单指令，已按用户要求删除，替换为 Qwen3.5-4B Q4_K_M。
3. 替换模型在 DSH 中实际执行一次本地文件读取，准确返回提示词未提供的随机内容，约 3.6 秒完成；重启隔离后台后会话仍保留。证据在 `build/site-capture-state/model-acceptance.txt` 与同名 PNG。模型配置使用用户在隔离设置中填入的凭据，未输出密钥。
4. `scripts/offline-loopback-guard.cjs` 可用于 Node 进程级非回环 TCP 拒绝试验；必须用外部地址负向探测和回环正向探测验证测试夹具。
5. 该夹具不是防火墙：不覆盖浏览器、LM Studio、自定义原生插件或非 Node 子进程。即使通过，也必须标注为受控断外网验证，不能写成整机物理断网通过。

## 企业分发的后续验收门槛

在一次性 Windows 环境中先准备完整包、WebView2 离线运行环境、模型权重和推理引擎，再隔离网络：新用户首次启动、模型列表、流式回复、本地工具、取消、重启、会话恢复、复制移动、独立修复。保留防火墙或虚拟网卡状态、进程与连接清单、模型版本和哈希、启动及请求日志。只覆盖实际测过的系统、内核、模型协议和插件组合。

## WebView2 封装和本机结果

微软 Fixed Version 152.0.4191.62 x64 的 548 个文件共 837,201,247 字节，官方 CAB 为 371,877,369 字节。保持全部文件，用现有 Zstandard 运行时容器封装后为 298,914,833 字节（约 285 MiB）。便携目录只增加压缩文件与两个小清单；首次运行在本机缓存展开，约 798 MiB 缓存占用仍然存在。未裁减语言、编解码器或其他运行文件。

Win11 隐藏原生窗口验收：空 WebView2 缓存准备约 2.27 秒，原生界面交接约 4.95 秒；缓存复用准备约 0.07 秒，界面交接约 3.82 秒。这是本机观测值，不是所有硬件的性能承诺。日志和进程路径均确认使用随包版本；系统运行时未卸载，因此也不将这项测试描述为无 WebView2 裸机验收。冷启动证据在 `build/webview-capsule-acceptance/cold-start.jsonl`。

构建入口：`scripts/build-windows-complete-offline.ps1`；微软 CAB 的来源、版本和 SHA-256 在 `config/webview2-runtime.lock.json`。Windows CI 已新增独立规格的构建和原生启动任务，尚未远程执行。固定版不由系统自动更新，后续更新锁定版本需经过同一验收；完整包不得长期携带未维护的浏览器运行时。Windows 10 的 AppContainer 权限已按微软文档接入，尚需对应环境验证。

普通 ZIP 继续轻量；完整离线包覆盖浏览器依赖，但不代表任意模型、插件、操作系统或企业限制均已通过验收。当前版本不应宣传“无需任何前置条件即可在任意电脑完全离线运行”。

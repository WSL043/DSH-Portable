# 0.8.0 之后的路线：清理旧实现，1.0 跟随官方桌面版

2026-09-29，用户确定方向。本文记录决定和可度量的现状，具体批次开工前仍以 [验收标准](native-release-exit-criteria.md) 与各任务记录为准。

## 已确定的方向

1. **1.0.0 以前的稳定版（0.x Native）只做极致优化，不再扩张功能。** 目标是同一套体验更稳、更小、更快、更容易维护。
2. **1.0.0-alpha 线重新构建，实现真正的 Portable。** 基于官方桌面成品与外置启动器（`experiments/official-payload/`），后续 alpha 从 alpha.4 起继续，仍为草稿/预发布，不替代 0.x 稳定版。
3. **官方桌面版正式推送后，Portable 跟随官方路线。** 官方成品保持原字节，Portable 只维护外置启动器、更新传输与插件市场入口；能用官方扩展点的不再自己打补丁。
4. **清理旧实现。** 旧代码里没有必要、重复或不是最佳的部分按下面清单逐项处理，每项独立验证。

## 批次（每批独立提交、独立验证，不混做）

1. **稳定版清理**：拆分 `DSH-Portable.cs`（先只搬移，不改行为，用现有原生验收对照）；再拆 `portable-core.mjs`；合并重复的冒烟脚本逻辑（首批已完成：`scripts/lib/official-onboarding.mjs`）。
2. **补丁退役审计**：列出全部对官方产物的补丁，逐项确认官方是否已提供扩展点；不能退役的写明原因和精确摘要。
3. **alpha.4**：以官方桌面成品为基础重新构建；先补齐 [1.0.0 计划](release-1.0.0-plan.md) 中“旧用户迁移”“插件生命周期”“更新与恢复”三项的缺口。
4. **跟随官方**：官方桌面版正式发布后，用接入检查命令（`scripts/intake-upstream-core.mjs`）与监控工作流评估，同形版本自动记录，异形版本人工审查。

## 不做

不为“看起来更整洁”而改变已通过验收的行为；不放宽补丁的精确匹配；不删除官方包；不把 1.0 alpha 当作稳定版升级路径。

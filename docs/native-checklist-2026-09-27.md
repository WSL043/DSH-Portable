## 本次实现

- 后台运行时清理在候选发现中检查 1 秒及 100000 条目预算；达到预算保留尚未删除的目标并报告 limited。随后实测发现整棵运行时大小统计本身就接近 1 秒，可能使大目标每轮都无法回收，因此最终后台模式跳过非必要的体积预扫描，回收体积记为未知而非伪报 0。手动 CLI 清理保留精确统计，不受后台默认预算限制；精确统计使用目录迭代与最多 32 个文件大小查询。
- 宿主退出发送取消信号；运行时扫描与插件日志清理在安全边界退出，释放占用的锁，不再启动下一项工作。已经提交给操作系统的单次文件删除不能中途撤销，这不是所有文件系统操作都能在 1 秒内强制终止的承诺。
- 日志清理继续承接 `1c9da13`：重试陈旧空 operation 目录，仅非递归删除；占用、新文件、近期目录及未知内容保留。
- GC 锁与运行租约共用独占写入边界。部分写入后遇到 ENOSPC 时关闭句柄并移除自己创建的残留；EEXIST 从未取得文件所有权，不能删除他人的锁。故障后再次取得租约和清理实际通过。
- 新增真实 `DSH-Recovery.exe` 验收脚本，纳入 Windows 2022/2025 现有成品 UI 作业，复用其独立产品目录，不新增解包或重复构建任务。
- 扩展恢复操作时发现：缺失插件不能恢复、受保护官方组件不能暂停，两项正确拒绝被通用错误吞掉具体原因。现在使用独立错误码及固定中英提示说明下一步，不向公开错误转发动态插件名或路径。

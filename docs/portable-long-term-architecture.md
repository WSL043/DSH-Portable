# Portable 长期架构与投入决策

2026-09-26。基于现有启动器、更新及存储入口抽查，既有 A01–A34 审计、官方 RC2 源码与成品体积实测，以及下列公开文档形成的设计。不是全仓逐行审计，也不表示设计已实现；任务完成状态仍由原维护清单及精确成品证据决定。

## 产品目标

让用户可以把一个可运行的 DSH 工作环境搬走，在断网机器继续使用，升级失败能恢复，长期使用的程序与缓存占用可解释。官方提供 Agent、账号、聊天、插件执行和桌面交互；Portable 提供可验证的环境交付与生命周期管理。

衡量长期价值的是旧环境升级成功率、离线恢复成功率、首次可操作时间、更新传输量、可回收空间和每次上游升级需要修改的适配点。Star 是传播结果，不是可靠性证据。官方若吸收便携模式，项目应收敛为发行与验收工具，而不是为了保持差异再造桌面功能。

## 技术路线决定

- Windows/macOS 下一代以官方 Electron Desktop 为目标底座。当前阶段发布可选试验通道，满足完整迁移与维护验收后再决定默认切换。Native 承担现有用户修复、轻量场景与 Linux；不要求两套界面永久功能对等。
- 原样官方二进制只有在数据根、更新归属、签名和平台运行都可验证时才可复用。若必须修改桌面源码，按独立社区构建处理，用自己的发行身份和签名；不能继承官方证书身份。先形成最小便携接口补丁，避免长期维护整套桌面 fork。
- 不为了体积再次改投第三套壳。Electron 的浏览器成本真实存在，但主线决策同时考虑重复补丁、平台行为与上游功能接入成本。Native 是否继续长期支持，应根据实际使用与维护成本评估，而不是提前强制迁移所有人。
- 先移植现有可复用的路径、事务和诊断逻辑，不创建通用包管理器、第二套插件安装后端或新的常驻管理服务。宿主差异通过小型适配器表达，不先设计大型抽象框架。

## 向优秀实现学习什么

| 来源 | 已核对的能力 | 对本项目的取舍 |
| --- | --- | --- |
| [VS Code Portable](https://code.visualstudio.com/docs/setup/portable) | 数据与程序邻接；Windows ZIP 不自动更新；通过搬移 data 更新 | 数据根契约比壳样式重要。我们的可验证更新与恢复可提供额外价值，但不能声称便携目录是独创能力 |

| [官方 DSH Desktop RC2](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/apps/desktop/README.md) | 固定桌面/运行时组合；官方插件页；完整桌面更新 | 官方管理所有通用交互和插件事务。Electron 不再提供任意内核与壳混搭 |

## 一个环境、一个写入所有者

建议逻辑布局如下；这是新模式契约草案，不立即重排现有安装目录：

```text
Portable/
  launcher             # 最小启动与离线恢复入口
  versions/<identity>/ # 不可变的已验证程序组合
  data/                # 会话、配置、附件、插件 profile
  workspace/           # 默认工作区；外部工作区显式记录
  cache/               # 可重建内容与未完成下载
  recovery/            # 事务记录及受保护的恢复材料
```

目录身份采用随机环境 ID，程序身份绑定版本、平台与摘要，不能由绝对路径决定逻辑身份。移动后重新解析路径，不复用旧机器进程租约。进程锁要区分同名 PID、不同机器和旧启动；未知所有权先保留。不要以“便携”宣称操作系统完全无痕：临时文件和系统凭据设施可能位于目录外，必须列明持久数据范围。

Native web profile 与 Electron desktop profile 不共用可执行插件依赖或锁文件。迁移使用官方数据格式与受支持导入路径；先在独立目标做转换并验证，再切换入口。用户工作区不靠复制配置中的绝对路径假装迁移完成。

插件安装、启用、禁用、卸载和取消由官方 Plugin Manager 执行；Portable 仅提供发现、版本信息及官方缺少的必要入口。页面读取同一个任务结果，保留 applied / restart-required / failed 的含义。插件加载失败不能让整个管理和恢复入口同时失效。

## 更新、恢复和支持生命周期

Electron 采用完整组合更新，Native 仅在既有兼容矩阵内保留独立内核更新。对每个安装目录只有一个更新执行者；官方自更新与 Portable 更新不能同时运行。签名来源、下载摘要、兼容身份分别验证，哈希本身不证明可信发布者。

先下载和验证完整候选，确认磁盘余量及旧进程退出，再进行可恢复切换。程序回退只处理程序文件；若新内核可能迁移数据，必须用受支持的快照/隔离目标验证，不能在新数据已写入后自动用旧程序继续打开。没有明确的数据兼容证据就暂停升级并保留当前可用环境。

恢复分为：启动/认证诊断、停用故障插件的安全启动、修复可重建程序、恢复程序版本、显式恢复数据。每项报告实际做了什么。401 不能归入“文件存在所以正常”；插件错误不能靠重建浏览器缓存解释；失败的数据恢复不能被启动健康检查掩盖。

建议支持策略（待落实到机器可读支持表，不追溯删除用户文件）：

- 活跃维护当前与上一条正式兼容基线；其他版本保留历史下载和说明，不无限补建所有旧版本组合。严重问题按受影响范围单独处置。
- 默认候选列表只展示当前环境可安装且经过验收的组合；历史版本明确支持状态，手动固定版本不被后台强制删除。
- 程序目录默认保留当前与一个可用回退版本；活跃租约、未完成迁移和用户固定版本优先保护。达到磁盘预算时提示，不能为满足数量上限删除保护项。
- 自动同步必须区分已发现、构建中、验收失败、等待上游、已发布、客户端可见。工作流总状态绿色不算推送完成；发布后回读公共索引和真实候选选择结果。

## 长期占用与性能

空间治理复用现有 storage-report 与运行时租约，建立当前版本、回退、插件 profile、离线修复包之间的引用关系。仅回收已证明无引用的再生内容；硬链接逻辑大小不当作可回收物理空间。现有 pnpm prune 曾破坏离线重建，因此先做“清理后移走 node_modules，再断网重建”的真实验证，才允许接入自动清理。

浏览器资源缓存、站点存储与登录凭据分开；手工备份不自动清除。回收错误可重试并报告占用原因。清理、全量统计和版本发现离开首屏关键路径；不为了界面数字每次启动扫描全部依赖。

[Windows RC2 压缩实测](official-electron-footprint.md)中的 solid 7z 是候选分发方式，而非已经选定的唯一格式。约 239.8 MiB 的压缩量与单次约 14 秒解包不能证明最佳首用体验。正式选择要比较下载、解压、首次可操作总时长，以及更新传输量、恢复时间；高密度 solid 会影响随机提取与差分复用，整包压缩和按稳定组件分块要在真实连续版本上比较。不要自研压缩算法，不重复压缩已压缩大文件，不每次启动重新解包。

Office/Python 等大组件只有上游具备可选加载与完整离线预装契约时才拆分。优化必须保留官方功能；功能删减不计为性能提升。跨平台不能照搬 Windows 的时间和压缩格式。

## 实施顺序和停止条件

以下承接既有 A/T/U/S/Q 清单，不建立第二套完成状态：

| 顺序 | 对应工作 | 可交付结果与完成证据 |
| --- | --- | --- |
| 1 | A04/A15、Q01、当前发布阻断 | 下一份官方不可变包能读取真实旧会话、继续执行；默认插件真实更新/启停/卸载通过；公共内核索引回读成功。未通过不靠迁移框架绕过 |
| 2 | 官方 Desktop 开发线 | 一个可重复构建的隔离 Electron 便携原型：同机换目录、跨机、断网冷启动、正常退出、故障插件恢复、账号重新认证、唯一更新者。现有欢迎页探针只覆盖其中一小部分 |
| 3 | A07/A08、默认插件边界 | 官方插件事务和 UI 接管；关闭插件后其扩展全部消失。删除重复页面与死路由，每个移除绑定官方替代能力和回归证据 |
| 4 | S01、U01–U03 | 可解释的空间预览、引用保护、离线重建验证、更新/迁移中断恢复；不会清除工作区或静默降级数据 |
| 5 | Q01、CI 性能计划 | 快速契约检查与平台成品验收分层；精确产物构建一次复用。只在新变更/新失败理由下复跑，不用无限重试换绿色 |
| 6 | Electron 默认切换评审 | 冷启动、后续启动、内存、占盘、升级与恢复均有对照；说明签名身份和已知限制，老用户可选择保留 Native。未满足继续试验通道 |

发布实验包不承诺所有平台可迁移账号；默认方案应允许重新登录，不因追求跨机免登录而把令牌明文落盘。需要加密导出时另立威胁模型与显式操作，不把这类复杂度加入首个原型。

## 降低长期维护成本

新增适配需写明上游版本范围、必要性、失败策略、退出条件和成品证据。可选文案/布局适配失配时禁用并报告，数据/认证边界失配时阻止危险操作。避免从压缩后代码的文字匹配推断完整 API 兼容。

每次上游接入先读桌面、插件 API、数据格式和发行布局变化，再决定删除哪些补丁。版本号只用于定位候选，不能替代能力检测与固定依赖闭包。补丁数量、反复失败项、CI 总时长和人工修复时间持续记录；重复出错的边界优先收敛，而不是不断增加兼容分支。

文档只保留一个当前决策入口；历史决定明确标为历史，避免同时出现“立即转向官方 Desktop”和“不启动 Electron 开发”的冲突。对外 README 用可验证的搬迁、断网、恢复示例表达价值，不承诺永远最小、绝对不丢数据或官方认证。

# Electron Alpha 1：发布边界与自审

该版面向愿意在全新目录体验官方 Electron 的 Windows x64 用户。不是 Native 版原地升级，也不是 1.0 功能完成声明。官方桌面与内核固定为 `0.1.7-rc.2`，源码提交 `477b4f420553e8a52c2fbccc464d7561b239c443`。

## 已实现的责任边界

| 部分 | 本版决定 | 验证方式 |
| --- | --- | --- |
| UI、插件、模型与会话 | 使用官方资源及官方插件管理，未搬入旧 Native DOM 补丁 | 成品页面、原生依赖与本地插件生命周期 |
| 数据目录 | EXE 同级 `data`；源码启动才传专用环境变量 | 全新启动、搬迁、重启，路径单测 |
| 宿主监听 | Desktop host 启动端口由固定 19387 改为 0，由系统分配；沿用官方 endpoint IPC 和认证 | 保留另一台本机实例的 19387 监听，新实例使用独立 loopback 端口 |
| 旧数据 | 无 Alpha 格式标记的已有 data 拒绝启动，先检查后写入 | 原数据不变测试；原生错误拒绝检查 |
| 插件缓存与搬迁 | pnpm store 固定在 `data/pnpm-store`；对已标记的 pnpm 11 hoisted 布局仅重定位两项受管元数据 | 安装后搬迁再卸载；外部来源路径不自动改写 |
| 更新 | 禁用官方安装器更新和强制升级；无公共更新索引 | 实际适配协调器测试，公开预发布 `latest=false` |
| 分发身份 | 通用 Electron EXE + 社区编译主进程，明确非官方签名发行 | 成品摘要、来源记录、发行说明 |
| 体积 | 暂保留完整官方运行库，先保功能再按实测裁减 | 原生 payload 测试；记录 ZIP 与解压体积 |
| 测试污染 | 只在 ZIP 的独立解压副本操作；公开 ZIP 不含 data/测试插件/凭据 | Alpha 发布门槛逐项检查 |

代码审计修正了已有数据的格式检查与日志目录重置。随后实机发现固定端口冲突导致 Loading plugins：新增经过源摘要锁定的一行宿主启动适配，使用官方已支持的端口 0。重新编译宿主并更新该文件的运行时完整性记录，不关闭原有进程，不探测后抢占端口，不回退到其他实例。除社区桌面适配外不能声称整个宿主字节完全未修改。新增数据标记不是对抗恶意本机修改的沙箱，也不能把向已有 Alpha 手动塞入旧会话变成受支持的迁移。

## 验收与后续设计

发布要求全新启动、真实编辑器输入、插件安装/启停/卸载、目录移动、无任务退出、原生运行库和亮色视觉验收；用最终 `app.asar` 与 EXE 摘要绑定结果。按钮验收使用 CDP 输入事件，不能只调用 DOM `.click()` 并把请求成功当结果。界面开关还须核对测试插件的实际启停标记。

后续按此顺序推进：

1. 明确数据格式升级路径，迁移预检和失败不修改旧数据；跨机凭据单独设计，不承诺复用系统加密态。
2. 整套应用更新、校验、事务切换、健康检查及独立恢复；更新只保留一个所有者。
3. 逐项核对官方已接管的归档/删除、图片和插件能力；只有真实缺口才保留 Portable 插件。
4. 设计空间占用展示和安全清理：用户内容、可重建缓存、回退版本分开；验证断网重建后再实施清理。
5. 冷启动、更新传输、长期资源趋势与 Native 对比；依据数据选择压缩和分包方式，不靠删除官方能力瘦身。
6. macOS、暗色/DPI、真实账号与模型、联网插件更新及失败恢复完成后，再讨论正式版。

本版不宣称以上待办已完成，也不把本机成品验收称为跨平台 CI 或安全审计认证。
